# Essay Format

Used for `form: "essay"` — long-form reflection, explainers, and pieces that work through
an idea rather than argue a single position. The essay **explores and arrives**. Voice
comes from `get_writing_context`; this file governs structure.

## Structure

Markdown with `title` and `subtitle` held separately (no H1 in the body).

### 1. Title + Subtitle

- **Title:** evocative but legible, 3-10 words. It may name the central image or idea
  rather than the conclusion.
- **Subtitle:** 1 sentence, ≤ 200 characters — what question the essay takes up.

### 2. Opening (1-2 paragraphs)

Open with a specific: a moment, an object, an exchange from a past episode, a detail
that carries the theme. By the end of the opening, name the **question** the essay is
pursuing. Do not announce the conclusion yet.

### 3. Body (4-7 sections)

- Use H3 subheads for each movement of the idea (2-6 words each). Each section is 2-4
  paragraphs of 3-6 sentences.
- Move the idea forward each time: context → complication → a different angle → what it
  changes. Each section should leave the reader knowing something the last didn't.
- Mix registers: concrete examples, history, the series' own conversations (from the
  archive), and reflection. Quote transcripts and articles you actually read.
- Explanatory passages define terms plainly the first time they appear.

### 4. Turn (1 section or paragraph)

The essay's pivot — where the evidence reframes the opening question. This is the
essay's reason to exist; make it explicit.

### 5. Close (1-2 paragraphs)

Arrive at a conclusion or a better question, and echo the opening specific so the
piece feels whole. End on an image or a line, not a summary of the sections. Add the
scope's `signoff` if set.

## Length

1,200-2,500 words by default; follow `articleConfig.articleLength` when set (short ≈
900-1,200, long ≈ 2,500-3,500).

## Avoid

- A thesis-first, five-paragraph shape — that's an opinion piece
- Sections that repeat rather than develop
- Ornate filler and stacked metaphors; one strong image per section is plenty
- "In conclusion" / "Ultimately" / "At the end of the day"
- Asserting current-events facts from memory — flag them for verification
- Reusing facts or quotes from exemplars
